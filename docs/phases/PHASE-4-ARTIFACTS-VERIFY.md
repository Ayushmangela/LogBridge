# Phase 4 — artifacts by reference: **verify, do not rebuild**

⚠️ Same warning as Phase 3. The table exists:

```sql
CREATE TABLE IF NOT EXISTS artifacts (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  task_id TEXT, attempt_id TEXT,
  creator_id TEXT NOT NULL,
  kind TEXT NOT NULL,
  title TEXT NOT NULL,
  summary TEXT,
  file_path TEXT,
  created_at TEXT NOT NULL,
  FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE
);
```

Referenced in **12 non-schema files** including `retention.ts` and
`deadLetter.ts`. Metadata-in-DB, bytes-on-disk (`file_path`) is already the
shape the report recommended. Good.

## The actual question this phase answers

**Do agent messages carry artifact ids, or do they carry content?**

That is the whole point. The table can be perfect and the benefit zero if
`sam` still pastes a diff into the message body. Check real messages:

- the samsung hive's `inbox/.done/` files
- whatever the wake path now delivers

If a message body contains a diff, a file listing, or more than a paragraph of
code, the reference model is not being used regardless of what the schema
says.

## Why this matters more now than when the report was written

Phase 0 made agent conversation **visible in the room**. Every agent message
posts a line to chat. If agents paste diffs, the office becomes unreadable
within an hour — a wall of code where the conversation should be.

So artifacts-by-reference is no longer just a token saving. **It is what keeps
the office legible**, which is the product.

## What to do

1. **Sample real messages.** Do not reason about it — read what is actually in
   the inboxes.
2. **If content is being inlined:** the fix is in the agent prompts
   (`hivePrompt.ts`), not the schema. Agents must be told to write the
   artifact and pass the id. That is a prompt change plus a helper they can
   call.
3. **Give agents a way to create one.** If writing an artifact is harder than
   pasting text, agents will paste text. Check the ergonomics before blaming
   the prompt.
4. **Cap `say`.** Phase 0 truncates at 280 characters. Confirm that holds for
   messages generated by real agents, not just the tests.

## What to be suspicious of

1. **`summary` written by nobody.** Columns added speculatively during
   unattended work. `SELECT count(*) FROM artifacts WHERE summary IS NOT NULL`
   answers it.
2. **Orphaned files.** `file_path` pointing at bytes that were deleted, or
   bytes with no row. Retention exists (`retention.ts`) — check which way it
   cleans.
3. **Path traversal.** `file_path` is attacker-adjacent if any agent controls
   it. Confirm it cannot escape the project directory. This project already
   fixed one traversal-shaped bug in static serving.

## Done when

- You can show a real developer→reviewer handoff that carries an id, and the
  reviewer fetching by that id.
- No message body in a live hive contains a diff.
- The office remains readable after a busy exchange between two agents.
